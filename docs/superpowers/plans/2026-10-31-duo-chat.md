# duo-chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A private two-person PWA (chat + ping + voice/video calls) for two 6-year-olds, open source and verifiable.

**Architecture:** Vue 3 PWA talks to one Cloudflare Worker + one Durable Object per pair over a WebSocket. The server only sees metadata and sealed (E2E-encrypted) WebRTC signaling; chat text goes device-to-device over a WebRTC data channel. Product rules (call attempts, ping pushes, presence) are pure functions on the server; the client renders server-computed views.

**Tech Stack:** Vue 3.5, TypeScript 6, Vite 8, Vitest 5, Vant 4 (UI), Cloudflare Workers + Durable Objects + Realtime TURN, Web Push (VAPID), WebCrypto, pnpm 10, Node 24.

**Spec:** `docs/superpowers/specs/2026-10-31-duo-chat-design.md`. UI framework research: `docs/ui-framework.md`.

## Global Constraints

- Contracts already in the repo are fixed; change them only by reporting back: `src/shared/*`, `src/client/session/types.ts`, the exported signatures in every stub file.
- Unit tests already in the repo encode the owner's rules; make them pass, do not weaken them. Add tests, never delete.
- Timings come only from `src/shared/constants.ts`.
- No third-party network requests at runtime: no CDN, remote fonts, analytics. Everything bundled.
- No `eval`, no inline `<script>`, no runtime `<style>` injection (strict CSP `script-src 'self'; style-src 'self'`).
- UI copy in Russian, icon-first, touch targets ≥ 56px. Code, comments, commits in English.
- Chat text never reaches the server. The pair secret never reaches the server.
- `pnpm test` and `pnpm typecheck` green at the end of every task.
- Each task works in its own git worktree and branch (`wt/<area>`), commits there, never merges.

## Review Focus

1. iPad PWA suspended mid-call or mid-ringing: socket drops, comes back; server state must converge (caller cancel on hide, callee incoming still valid via push).
2. Both devices reconnecting at the same time (glare): perfect negotiation must not deadlock; tested in Task 4 with fake peer connections.
3. Clock skew between devices for message expiry: covered in Task 3 tests (clamp rule).
4. Durable Object restart (hibernation/eviction): `connected` flags in persisted state must be reset from live sockets on wake; Task 1 adds a test that a restored core with no sockets reports peer absent after grace.
5. Pairing link opened on iPad lands in Safari, not the installed app (separate storage on iPadOS): pairing must be done inside the installed app by scanning the QR or pasting the link (Task 5 screens, Task 7 flow).

**Files:** `src/server/rules/*.ts`, `src/server/room/core.ts`, `src/server/room/durable.ts`, `src/server/worker.ts`, new `src/server/push/webPush.ts`, `src/server/auth.ts`, tests next to them.

**Interfaces:**
- Consumes: `src/shared/protocol.ts`, `src/shared/constants.ts`.
- Produces: HTTP + WS API exactly as in `src/shared/protocol.ts`.

- [ ] Make `src/server/rules/*.test.ts` pass (pure functions, semantics in doc comments).
- [ ] Make `src/server/room/core.test.ts` pass. Semantics not visible in tests: after every event send a `view` to every connected side; "recipient reachable" for push decisions = `isPresent && connected`; `peerPresent` in views = `isPresent`; any call/ping/replied from X resets the other side's ping counter (`onPingReply`); X calling Y applies `onCalledBack` to Y's call state; caller hiding or disconnecting cancels its pending call; disconnect during an active call ends it with `hangup` for the peer.
- [ ] Add test: restored core (`new RoomCore(state)`) with sides marked connected but `connect` not called again — DO wake path calls `disconnect` for sides without a live socket; peer then turns absent after the grace.
- [ ] `auth.ts`: device tokens = 32 random bytes base64url; store only SHA-256 hashes; constant-time compare. Unit-test it.
- [ ] `durable.ts`: WebSocket hibernation API (`ctx.acceptWebSocket`, tags = side); first frame must be a valid `hello`; persist `RoomCore.state` + token hashes in `ctx.storage`; set `ctx.storage.setAlarm(core.nextAlarmAt())`; execute effects; on wake reconcile connected flags with `ctx.getWebSockets()`.
- [ ] `worker.ts` routes from `protocol.ts`: claim (admin bearer for 'a'), DELETE room (admin), ICE (device token → Cloudflare Realtime TURN `generate-ice-servers` API with `TURN_KEY_ID`/`TURN_KEY_API_TOKEN`, TTL 1h), VAPID public key, WS upgrade forwarded to the DO by `idFromName(roomId)`. roomId must match `^[A-Za-z0-9_-]{22}$`.
- [ ] `push/webPush.ts`: Web Push with VAPID (RFC 8291 aes128gcm + RFC 8292) using WebCrypto in Workers; a small vetted library that runs on Workers is fine. 404/410 from the push service deletes the stored subscription. Unit-test the payload encryption against an RFC 8291 test vector or the library's own vectors.
