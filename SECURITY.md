# Безопасность

Здесь только то, чего не видно из кода. Остальное — в самом коде, ссылки ниже.

## Модель доверия

- Серверу (Cloudflare Worker) содержимое не доверено. Ключей у него нет.
- Переписка идёт напрямую между двумя устройствами (WebRTC data channel) и через сервер не проходит.
- Звонки — WebRTC: шифрует браузер (DTLS-SRTP). TURN-ретранслятор видит только шифрованные пакеты.
- Сигналинг WebRTC (SDP, ICE-кандидаты) шифруется и подписывается на устройстве общим ключом пары (AES-GCM). Сервер не может ни прочитать его, ни подменить отпечатки DTLS, чтобы встать посередине звонка.
- Секрет пары создаётся на первом устройстве и попадает на второе во фрагменте ссылки (`#…`). Браузер не отправляет фрагмент на сервер.

## Что сервер всё-таки видит

- когда каждое устройство подключилось и отключилось (и IP-адрес соединения — его видит Cloudflare);
- события звонков (кто звонит, принят, отклонён, пропущен) и нажатия кнопки «позвать»;
- адреса push-подписок (endpoint у Apple/Google/Mozilla) и счётчики уведомлений;
- имена и выбранные аватарки, которые взрослый ввёл при создании пары.

Тексты сообщений, звук, видео и секрет пары сервер не видит.

## Куда смотреть

- `src/client/crypto/pair.ts` — секрет пары, вывод ключей, шифрование сигналинга.
- `src/shared/protocol.ts` — всё, что клиент и сервер передают друг другу.
- `src/server/room/core.ts` — что сервер хранит и что делает с событиями.
- `public/_headers` — Content-Security-Policy: никаких сторонних адресов, скрипты и стили только свои.
- `scripts/verify.ts` — проверка, что сайт собран из этого репозитория.

## Как проверить, что сайт собран из этого кода

Сайт публикуется только из GitHub Actions (`.github/workflows/deploy.yml`, лог открытый). Сборка воспроизводимая: тот же коммит даёт побайтово те же файлы. Сайт отдаёт `/version.json` — коммит и SHA-256 каждого файла.

```sh
git clone <ссылка на репозиторий> && cd duo-chat
corepack enable && pnpm install --frozen-lockfile
node --experimental-strip-types scripts/verify.ts https://<адрес сайта>
```

Нужны git, Node той версии, что в `.node-version`, и pnpm. Скрипт скачивает `/version.json`, собирает указанный там коммит во временной папке, скачивает каждый файл с сайта и сравнивает хэши, а также заголовки безопасности. В конце печатает `PASS` или `FAIL` со списком расхождений.

Каждый файл сборки ещё и подписан аттестацией происхождения (Sigstore). Проверка одного файла:

```sh
gh attestation verify <скачанный файл> --repo <владелец>/duo-chat
```

## Честные ограничения

- Код Worker'а снаружи не проверить: `verify` сверяет только то, что получает браузер. Но у Worker'а нет ключей, так что подменённый сервер может только не доставить или задержать звонок, но не подслушать и не подделать его. Проверенный фронтенд — вся основа доверия.
- Метаданные из списка выше сервер видит, и это не скрыть.
- Устройство, на котором стоит приложение, доверенное: кто держит в руках разблокированный iPad, тот видит переписку.
- Ссылку для пары может использовать любой, кто её увидел, поэтому она одноразовая. Передавайте её лично или через надёжный мессенджер.
